Pipeline Flow: The CSV file is uploaded from the local machine to the source-data Blob container. 03 · Implementation

Step-by-Step Implementation Guide

1

Explore Azure Portal & Create Resource Group

Log in to the Azure Portal. Navigate to Resource Groups → Create. Set the name to rg-superstore-pipeline, select region East US, and add tags: Project=Assignment-4, Author=Ashmit Gupta. Click Review + Create → Create.

Azure Portal Resource Group East US Region
# Azure CLI alternative: az group create \ --name rg-superstore-pipeline \ --location eastus \ --tags Project=Assignment-4 Author="Ashmit Gupta"
2

Create Storage Account & Blob Containers

In the Resource Group, click Create → Storage Account. Name it stashmitsuperstore01 (must be globally unique). Set Performance: Standard, Redundancy: LRS. After creation, go to Containers → + Container and create two containers: source-data and destination-data (both Private access).

Storage Account Blob Container LRS Redundancy Private Access
# Azure CLI alternative: az storage account create \ --name stashmitsuperstore01 \ --resource-group rg-superstore-pipeline \ --location eastus \ --sku Standard_LRS \ --kind StorageV2 # Create containers: az storage container create --name source-data --account-name stashmitsuperstore01 az storage container create --name destination-data --account-name stashmitsuperstore01
3

Upload Superstore CSV to Blob Storage

In the source-data container, click Upload. Browse and select Sample - Superstore.csv (9,994 rows, ~2.3 MB). Confirm upload. The file will be available at: https://stashmitsuperstore01.blob.core.windows.net/source-data/Sample - Superstore.csv

CSV Upload 9,994 Rows ~2.3 MB
# Azure CLI upload: az storage blob upload \ --container-name source-data \ --account-name stashmitsuperstore01 \ --name "Sample - Superstore.csv" \ --file "Sample - Superstore.csv" # Or use the Python script: scripts/upload_and_validate.py python scripts/upload_and_validate.py
4

Create Azure Data Factory & Explore ADF UI

Navigate to Create a resource → Azure Data Factory. Name it adf-ashmit-superstore, same resource group, East US, Version V2. Enable Git if needed (optional for this assignment). Click Create. After deployment, click Launch Studio to explore: Author (create pipelines), Monitor (view runs), Manage (linked services, IR).

ADF Studio Author Tab Monitor Tab Manage Tab
5

Create Linked Services (Source & Destination)

In ADF Studio → Manage → Linked Services → New. Choose Azure Blob Storage. Name it LS_AzureBlobStorage_Source. Use Account Key authentication, select the storage account stashmitsuperstore01. Click Test Connection → Create. Repeat for LS_AzureBlobStorage_Destination.

Linked Service Blob Storage Auth Connection Test ✓
6

Create Datasets (Source & Destination)

In ADF Studio → Author → Datasets → New Dataset. Choose Azure Blob Storage → DelimitedText (CSV). For Source: use LS_AzureBlobStorage_Source, container: source-data, file: Sample - Superstore.csv, First row as header: ✓. For Destination: use LS_AzureBlobStorage_Destination, container: destination-data, folder: processed/, dynamic filename via expression.

Source Dataset Destination Dataset DelimitedText / CSV Dynamic Filename
7

Get Metadata Activity — File Validation

In a new pipeline, drag Get Metadata activity. Set Dataset to DS_Source_SuperstoreCSV. Select field list: exists, itemName, itemType, size, lastModified, columnCount. This validates the file before attempting to copy, preventing pipeline failures due to missing source files.

Get Metadata File Existence Check Column Count Validation
// Get Metadata Output Sample: { "exists": true, "itemName": "Sample - Superstore.csv", "itemType": "File", "size": 2287806, // ~2.3 MB "lastModified": "2026-06-15T04:00:00Z", "columnCount": 21 }
8

Build Pipeline with Copy Data Activity

Add If Condition activity (checks if file exists), then inside its True branch add Copy Data activity. Source: DS_Source_SuperstoreCSV, Sink: DS_Destination_SuperstoreCSV. Set translation to Tabular Translator. Connect all activities with success dependencies. The complete pipeline: GetMetadata → IfCondition → CopyData → SetVariable(RecordCount).

Copy Data Activity If Condition Set Variable Tabular Translator
9

Execute Pipeline (Debug / Trigger)

Click Debug to run interactively and see output in real time. Or click Add Trigger → Trigger Now for immediate manual trigger. Monitor the run in the Monitor tab. All activities should show a green ✅ checkmark. The pipeline copies all 9,994 rows from source-data to destination-data/processed/.

Debug Run Trigger Now Pipeline Monitor 9,994 Rows Copied

04 · Pipeline

Pipeline Activity Flow

📋

ACT_GetMetadata_SuperstoreFile

Retrieves file metadata from the source Blob container: file existence, name, type, size (~2.3 MB), last modified timestamp, and column count (21 columns). Uses DS_Source_SuperstoreCSV dataset.

Get Metadata Timeout: 10 min Retry: 2x
⬇
❓

ACT_IfCondition_FileExists

Evaluates the expression: @equals(activity('ACT_GetMetadata_SuperstoreFile').output.exists, true). Routes to CopyData on True, and to Fail activity on False.

If Condition True → Copy False → Fail
⬇
📤

ACT_CopyData_SuperstoreCSV

Copies all 9,994 rows from source-data/Sample - Superstore.csv to destination-data/processed/superstore_processed_YYYYMMDD_HHmmss.csv. Uses Tabular Translator with type conversion enabled. Expected throughput: ~15 MB/s.

Copy Data CSV → CSV Timeout: 1 hr Retry: 2x
⬇
📊

ACT_SetVariable_RecordCount

Sets pipeline variable v_RecordsCopied to the row count from the Copy activity output: @string(activity('ACT_CopyData_SuperstoreCSV').output.rowsCopied). Records audit metadata.

Set Variable Audit Logging

05 · Security

IAM Role Assignments

Role-Based Access Control (RBAC) ensures the principle of least privilege. ADF uses a System-Assigned Managed Identity to authenticate against Blob Storage without storing credentials. IAM roles are assigned at the Storage Account level.

🔐 IAM Role Assignments — stashmitsuperstore01 ✓ Configured
Principal / Identity Role Scope Purpose Assignment Type
🏭 ADF Managed Identity
adf-ashmit-superstore		 Storage Blob Data Contributor Storage Account Read source & write destination blobs System-Assigned
👤 Ashmit Gupta
User Account		 Owner Resource Group Full resource management & IAM control User
🤝 Team Members / Reviewers Contributor Resource Group Create/edit resources, run pipelines Group / User
👁️ Observers / Viewers Reader Resource Group View-only access to all resources Group / User
🔍 Blob Readers Storage Blob Data Reader Storage Account Read blobs (downstream consumers) User / Service Principal
⚠️
Security Best Practice: Use Managed Identity (not connection string keys) for ADF→Storage authentication in production. Enable Diagnostic Logs on both Storage and ADF to audit access. Rotate Storage Account keys regularly.

Assigning IAM Roles (Portal Steps)

🔧 Step A: ADF Managed Identity Role

1. Go to stashmitsuperstore01 → Access Control (IAM) → Add → Add role assignment

2. Role: Storage Blob Data Contributor

3. Assign access to: Managed Identity → Data Factory

4. Select adf-ashmit-superstore → Save

👥 Step B: User / Team Roles

1. Go to rg-superstore-pipeline → Access Control (IAM) → Add role assignment

2. For each user: select role (Contributor or Reader)

3. Assign access to: User, group, or service principal

4. Select user email → Review + Assign
